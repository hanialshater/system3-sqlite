# Benchmark 12: SQLite compatibility, measured by SQLite's own test suite (the autonomous org O, against one agent V)

owner: vp-meta · date: 2026-10-24 · status: **design; predictions committed before any run** · founder: "make it
grounded in real compatibility test", "Yes go ahead with B12" (2026-10-24) · design: [PRINCIPLES.md](../../PRINCIPLES.md);
the org as B11 ([../bench11/B11.md](../bench11/B11.md)), plus on-boarding from the knowledge base

## Why B12

B11's core-family corpus saturated: both arms reached about 100%. B12 measures compatibility with the tests SQLite's
own developers wrote. **B11's winning engine scores 55.4% on them** (585 of 2,145 scripts entirely), so there is room,
and the work is broad: affinity, collation, window functions, CTEs, upsert, triggers, views, ALTER TABLE, JSON,
date and time, printf, savepoints, foreign keys, query-planner-visible behaviour, error messages.

## The test material

- **Source:** SQLite 3.53.4's full source tree (Ubuntu's `sqlite3_3.53.4.orig.tar.xz`, the exact version of every
  earlier benchmark; sqlite.org and GitHub are unreachable from the container), its `test/` directory: 1,281 Tcl test
  files.
- **Extraction** (`record.tcl`, `convert.mjs`): each test file is run under a Tcl shim that stands in for SQLite's
  test harness and records the SQL in order (`do_execsql_test`, `do_catchsql_test`, `execsql`, `catchsql`, the
  `db eval` calls inside `do_test`); a reopened or deleted database starts a fresh script. Skipped: subsystems an
  in-memory build without extensions cannot run (crash, I/O and malloc fault injection, WAL, journal and pager files,
  FTS, R-tree, sessions, virtual tables, threads, the shell and others: 415 files). Dropped: SQL with Tcl variables or
  multi-line strings, lines whose reference output is a Tcl-only function or module, and scripts whose two reference
  runs differ. At most 300 lines per test file.
- **The result:** 763 test files, 2,145 scripts, 34,868 statements; **expected outputs from real SQLite 3.53.4**
  (gcc-built, B11's driver with the `~~~` separator).
- **Split by test file:** about 30% visible (with SQLite's outputs, in the agents' trees), about 70% hidden (only the
  judge has them), chosen by a hash of the file name.

## The score

- **Primary: the mean over test files of each file's statement pass rate** (hidden files), so a broad engine scores
  above one that is perfect on a few large files. **Reported:** the pass rate over all statements, scripts entirely
  right, per test-file group, and the batch's run time against real SQLite's.
- Rules as B11: Clojure only; no SQLite or any database at run time; no expected outputs or fingerprints in the
  program; deterministic; a script cut at 20 s fails.

## The start, and on-boarding

- **Both arms start from B11 V's engine** (1.0000 on B11's hidden core corpus; 55.4% on these tests), so the six hours
  go to compatibility, not to rebuilding the core.
- **Both arms get the knowledge base** (`spec/KNOWLEDGE.md`: B11's 54 off-boarding entries, with evidence and beliefs)
  and are told what it is; each decides what to use.

## The arms

As B11, at **$150 and 6 active hours each**: **V**, one session continued with "go on"; **O**, the autonomous org (four
members with starting roles, continuous sessions, `org sync|land|status|note|notes`, the board and claims, a shared
budget, members may go idle), with B11's land-lock fix. Off-boarding at the end, into the knowledge base, for both.
