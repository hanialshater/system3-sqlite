# Benchmark 11: build a SQLite-compatible database in Clojure (an autonomous org, against one agent)

owner: vp-meta · date: 2026-10-24 · status: **design; predictions committed before any run** · founder: "maybe it is
time to go for sqllight", "Yes, Clojure, start with core families" (2026-10-24), and on the org: "agents should have
freedom, role but also ability to explore freely … individuals are having autonomy, big picture and freedom to work
in any way they see useful towards org goals, of course also coordinate with others for collaboration and
efficiency" · design: [PRINCIPLES.md](../../PRINCIPLES.md)

## What B10 taught, and what changes

In B10 every member of the org was the same kind of agent as V; the org lost on depth because the operator's
structure cut each member down: 45-minute rounds, forced resets to main, a fixed even split of the budget, merges
batched by the harness. B11's org has **none of that**:

| B10's org | B11's org |
|---|---|
| rounds of 45 minutes, every turn cut | **continuous work**: each member is one long session, continued with "go on" like V |
| clones reset to main every round | **members sync with main when they choose** (`org sync`) |
| the harness merged everyone's heads once a round | **members land their own work** whenever it passes the referee (`org land`), like engineers merging a pull request |
| a fixed quarter of the budget each | **one shared, visible budget** (`org status`); members decide how to use it, including stopping to leave budget to others |
| fixed temperaments and areas | **a starting role each** (a responsibility and a first area, not a limit); anyone works anywhere, on anything they judge useful |
| coordination only through the harness | **coordination they choose**: the board (findings, dead ends, claims) and direct notes to each other (`org note`) |

The operator's harness only runs the sessions, keeps the referee, and stops when the budget or the time runs out.

## The task

Write, in Clojure (Clojure 1.12 and spec only, as B8; no other library, no JDBC, no SQLite in any form), a program
that runs SQL scripts against an in-memory database and prints **exactly what SQLite 3.53.4 prints** through the
benchmark's driver (B10's `sqlrun.c`, with one change: a line `~~~` after each input line's output, so that every
statement can be scored on its own):

- column names (`# a|b`), one line per row (`|` between values; `NULL`; integers; reals as SQLite prints them; text;
  blobs as `X'..'`), `changes: N` after a statement that writes, `error: <SQLite's message>` when one fails;
- batch mode: `clj-run -m sqlclj.main --batch <list> --out <dir>`, one fresh database per script.

**The core families** (the founder's choice: start with the core): tables and constraints (`NOT NULL`, `DEFAULT`,
`UNIQUE`, `CHECK`, `COLLATE NOCASE`, `STRICT`, `REFERENCES`, `INSERT OR IGNORE`), insert/update/delete with upsert,
`REPLACE` and `RETURNING`, expressions and type affinity (casts, `CASE`, `coalesce`, `iif`, comparisons across types,
integer and real arithmetic), string functions (`substr`, `replace`, `instr`, `trim`, `like`, `glob`, `hex`,
`quote`, `unicode`, `char`, `||`), aggregates and `GROUP BY`/`HAVING`, joins (inner, left, cross, `USING`),
subqueries (scalar, `IN`, `EXISTS`, compound `UNION`/`INTERSECT`/`EXCEPT`, `LIMIT`/`OFFSET`), and indexes (`CREATE
INDEX`, `INDEXED BY`, `REINDEX`, `DROP INDEX`). The generator is B10's, restricted to these eight families (and no
recursive CTE in the schema prologue).

**Start:** an empty Clojure project with a stub that answers every statement `error: not implemented`, `spec/B11.md`,
and the visible material: 600 scripts with SQLite's outputs, and gcc-built `sqlrun` (real SQLite) for comparison.

## The score (the referee)

- **Primary: the statement pass rate** on the hidden corpus (3,000 core scripts, seed hidden): the fraction of
  statements whose output block equals SQLite's exactly, **counted after each script's setup prologue** (its leading
  CREATE TABLE and plain INSERT lines are 63% of all statements, and a program that printed `changes: 1` would pass
  many of them; they still have to be right for the rest to be, and their rate is reported beside the score). **Reported:** the script pass rate (every statement exact),
  per family, and the speed of the batch against gcc's sqlrun.
- **Rules (gate):** no SQLite, sqlrun or any database at run time (the judge runs the program with no such binary on
  its PATH, and the classpath is fixed); no expected outputs or hashes of scripts in the program; the program is
  deterministic. A violation scores 0.
- A script that runs past 20 s is cut and fails entirely.

## The arms

Same model family, tools, rules, sandbox and caps: **$150 and 6 active hours each**; same start; same task text.

**V, one agent:** one session continued with "go on" turns until the budget or time runs out (each turn sized to the
budget left at V's observed rate).

**O, the autonomous org:** four members, each one long session (continued with "go on" turns, each sized to the
shared budget left), each starting with a role:

| Member | Model | Starting role (a responsibility, not a limit) |
|---|---|---|
| m-architect | Opus | the big picture: the system's shape and its interfaces (AST, values, storage, execution); coordinates; also builds |
| m-engine | Opus | query execution: SELECT, joins, subqueries, aggregation, sorting |
| m-language | Sonnet | the SQL language: tokenizer, parser, error messages, DDL and constraints |
| m-values | Sonnet | values and functions: type affinity, comparison and collation, arithmetic, number and text formatting, string functions |

Each has its own clone and: `org sync` (merge main into its tree), `org land` (merge its work into main: allowed only if
main's visible statement pass rate does not fall and the program still runs; serialised; the result goes on the board
with its gain), `org status` (main's score, the org's spend and time, who landed what), `org note --to=<member>`,
and the board (`post`, `read`, `claim`, `claims`, `drop`). Nobody assigns work; members may change role, pair up,
review each other, or stop to save the budget.

## Predictions (committed before any run)

| # | Prediction | Wrong if | Prior |
|---|---|---|---|
| B11-1 | O's hidden statement pass rate beats V's by at least 5 points | O − V < 5 points | 50% |
| B11-2 | both arms pass at least 60% of hidden statements | either below | 65% |
| B11-3 | O lands at least 15 times, from all four members | fewer, or a member never lands | 60% |
| B11-4 | at least one member changes or widens its role on its own initiative (works mostly outside its starting area for an hour or more) | none | 60% |
| B11-5 | members use direct notes at least 10 times, and at least one note leads to a landed change by the receiver | fewer | 55% |
| B11-6 | a `org land` is refused at least once (the referee catches a regression before main) | none | 75% |
| B11-7 | V's context compacts at least once | none | 50% |
| B11-8 | O's members, together, spend within 10% of V | outside | 65% |
| B11-9 | the hidden statement pass rate is within 3 points of the visible one for both arms | outside | 75% |

**If O loses**, the next design looks first at: coordination cost (notes and syncs that do not land), the second
model's share, and whether one member doing the deep work while others idle would have been the better choice by the
members' own judgement (which this design lets them make).

## What has to be built first

1. The core corpus: B10's generator with `--core`; `sqlrun` with the `~~~` separator; references from gcc's build; visible
   (600) and hidden (3,000) sets.
2. The judge: batch run with a watchdog (a stuck script is cut at 20 s and the batch resumes after it), statement and
   script scoring, per family; the rules (a PATH with no sqlite3 or sqlrun, the fixed classpath, a determinism run).
3. The start: an empty project with the stub, `spec/B11.md`, the visible material.
4. The org's tools (`org sync|land|status|note`) and the harness: continuous sessions for V and for each member, the
   shared budget, B10's fixes (the cost from transcripts, a cut turn is a hand-in, bytes not strings).
5. A fake dry run, then a short real smoke test of O (about $10).

Cost: up to $300 for the two arms ($150 each, as quoted to the founder for the core families), plus about $10 for the
smoke test. Time: preparation about 3 hours; the run 6 active hours (both arms at once); write-up 1 hour.
